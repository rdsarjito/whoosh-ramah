## Overview

This repository is a multi-language hackathon project with two independent codebases that each manage their own dependencies:

1. **Flutter app** (`whoosh_ramah/`) — uses Dart's `pub` package manager.
2. **Python detector** (`detector/`) — uses `pip` via `requirements.txt`, with the runtime Python version pinned by `mise.toml` at the repo root.

There is no shared lockfile or monorepo dependency orchestrator; each subproject is self-contained.

## Flutter (Dart) Dependencies

- Declaration file: `whoosh_ramah/pubspec.yaml`
- Lockfile: `whoosh_ramah/pubspec.lock` (generated by `pub`, includes `sha256` digests and `https://pub.dev` hosted URLs for every resolved transitive dependency)
- SDK constraint: `environment.sdk: ^3.14.0`
- Direct dependencies declared under `dependencies:`:
  - `flutter` (from `sdk: flutter`)
  - `material_ui: ^1.1.0`
  - `cupertino_icons: ^1.0.8`
  - `firebase_core: ^5.2.0`
  - `cloud_firestore: ^7.2.0`
  - `intl: ^0.20.3`
- Dev dependencies under `dev_dependencies:`:
  - `flutter_test` (from `sdk: flutter`)
  - `flutter_lints: ^6.0.0`
- The package is marked private: `publish_to: 'none'` in `pubspec.yaml`.
- All packages resolve from the public `https://pub.dev` registry; no custom `pubspec_overrides.yaml` or private repository configuration is present.
- Assets (Nunito fonts) are vendored locally under `whoosh_ramah/assets/fonts/` and registered in the `flutter.fonts` section of `pubspec.yaml` so they ship with the app without network access during demos.

## Python Dependencies

- Declaration file: `detector/requirements.txt` (flat list, no `pip-tools` / `pipenv` / `Poetry` lockfile):
  ```
  opencv-python>=4.8
  python-dotenv>=1.0
  firebase-admin>=6.4
  inference-sdk>=0.20
  ultralytics>=8.2
  ```
- Version constraints use `>=` lower bounds rather than exact pins, so `pip install -r requirements.txt` resolves to the latest compatible versions at install time.
- No virtual environment is committed; `detector/venv/` exists but is gitignored (see `.gitignore`).
- Runtime Python version is pinned centrally by `mise.toml`:
  ```toml
  [tools]
  python = "3.12"
  ```
  This is consumed by the `mise` tool installer to provision the correct interpreter before running the detector scripts.

## Android / Gradle (transitive)

The Flutter Android build layer declares its own dependencies through Gradle (`android/build.gradle.kts`, `android/app/build.gradle.kts`, `android/settings.gradle.kts`) and ships a vendored Gradle wrapper (`android/gradle/wrapper/gradle-wrapper.jar` + `gradle-wrapper.properties`). These are standard Flutter-generated files and are not edited as part of application dependency management.

## Conventions Observed

- Each language subproject owns its own manifest; there is no cross-project dependency resolution.
- Flutter dependencies are pinned deterministically via `pubspec.lock` (committing the lockfile ensures reproducible builds).
- Python dependencies are intentionally loose (`>=`), trading reproducibility for simplicity in a hackathon context.
- The Python runtime version is centralized in `mise.toml` rather than specified per-package.
- Fonts are vendored directly into `assets/fonts/` instead of being pulled from an external font CDN, documented in `pubspec.yaml` with the comment "Font Nunito dibundel lokal agar tidak butuh internet saat demo" (bundled locally so no internet is needed during demos).
- No private registries, proxy mirrors, or vendored third-party source trees are configured beyond the standard Flutter/Gradle artifacts.
