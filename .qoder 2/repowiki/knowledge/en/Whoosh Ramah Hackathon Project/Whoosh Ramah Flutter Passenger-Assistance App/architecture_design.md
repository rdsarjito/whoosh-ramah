The app is layered in three concentric scopes under `lib/`:
- `main.dart` (app_shell) initializes Firebase via `firebase_options.dart`, configures the global `ThemeData` from `theme.dart`, and launches the root `MaterialApp`.
- `shared_layers` provides the `Permintaan` domain model plus its `PermintaanService` (Firestore CRUD + demo data) and reusable widgets consumed by every screen.
- `penumpang_flows` implements the passenger-facing screens (ticket display, companion request, status tracking) which depend on both the shared layers and the app shell's theme.
Cross-child wiring happens through Dart imports: screens import shared models/widgets, and the app shell owns the single Firebase/Firestore client instance. Android platform code (`android/app/src/main/kotlin/id/kcic/whoosh_ramah/MainActivity.kt`) is the native entry point generated by Flutter with no custom logic beyond the plugin registrant.
