Four sub-folders with a strict one-way dependency direction: `data/dummy.dart` is a leaf of hard-coded demo entities (`PenumpangDummy`, `PetugasDummy`, `TiketDummy`, `DummyData`) with no app dependencies; `models/permintaan.dart` defines the immutable domain types (`JenisBantuan`, `StatusPermintaan`, `RiwayatStatus`, `Permintaan`) plus paired `fromFirestore`/`toFirestore` factories and enum-to-string round-trips via `dariValue`; `services/permintaan_service.dart` wraps the `permintaan_pendampingan` Firestore collection, exposing stream-based reads (`streamPermintaan`, `streamSemua`, `streamTerbaruPenumpang`) and mutations (`buatPermintaan`, `majukanStatus`, `tandaiTiba`), and injects an optional positional `FirebaseFirestore` constructor parameter so production uses `FirebaseFirestore.instance` while tests supply a mock; `widgets/` holds presentation-only components (`bottom_nav.dart`, `pill_button.dart`, `white_card.dart`, `hero_header.dart`, `lembar_tiket.dart`, etc.) that consume `AppColors`/`AppRadius` from the app theme. The service depends on both `models` and `data`; widgets depend only on the app theme — there is no cross-import between models and widgets.
